01 What the app is

StandIn is a local-first privacy desk for using AI on confidential documents. It finds likely people, organizations, locations, emails, phone numbers, and identifiers in a document; gives each accepted entity a stable token; produces a tokenized safe copy; checks that copy for known leaks; and restores the real details in the AI's answer.

The proof of concept is one browser tab with no account, backend, database, or API key. The document and cast live in React memory for the session only. The bundled language model runs in a Web Worker on the same machine; the app fetches its static files from its own origin and does not send document text to a server. The user's AI assistant is a separate tool that the user controls by copying text into it.

The deskThree steps: prepare and review, safe copy, restore.
DetectionPattern rules plus a local DistilBERT NER model.
The castGrouped mentions with stable tokens and a human review.
The loopTokenize, leak-check, copy, restore the answer.
The boundaryNo persistence. A refresh loses the work by design.

02 One action through the system

1
Load a document and choose “Scan locally.” src/components/DocumentEditor.tsx collects the text; src/components/PreparePanel.tsx passes onScan={standIn.scan}.
↓
2
The hook scans patterns and sends chunks to the local model. src/hooks/useStandIn.ts calls findPatternDetections, then the Worker through src/hooks/useWorkerScanner.ts. src/lib/ner.worker.ts loads the bundled ONNX model.
↓
3
Detections become a reviewable cast. src/lib/detections.ts merges pattern and model results; src/lib/cast.ts groups mentions and assigns tokens.
↓
4
The safe copy and restore use the same cast. src/lib/tokenize.ts writes the tokens; src/lib/leakCheck.ts checks the result; src/lib/restore.ts reverses known tokens in the AI's answer.
Outside the app: the user pastes the safe copy into their own AI tool. That tool's privacy terms apply. StandIn never calls it.

Stop 3 — Follow the safe copy and the restore

Both directions read the same cast snapshot. That shared snapshot is what makes the loop reversible: the safe copy is not just redaction, and restore is not a second guess at who was who.

  • src/hooks/useStandIn.ts — search const createSafeCopy and const restore.
  • src/lib/tokenize.ts — search tokenizeDocument.
  • src/lib/leakCheck.ts — search checkLeaks.
  • src/lib/restore.ts — search restoreTokens and LOOSE_TOKEN.
  • src/components/SafeCopyView.tsx and src/components/RestoreView.tsx — the two result surfaces.
Visible result: the sample safe copy is 1,068 characters with 19 stand-ins and 29 token mentions; the known-residual check returns none. A pasted answer using the tokens restores the real names, email, and money; an invented token such as [PERSON_9] stays visible and is reported.

05 A practice to reuse

Turn each visible promise into a check you can run.

The safe copy makes a concrete promise: no known sensitive values remain. During the final browser check, the visible result was compared against the sample's actual names, emails, account, card, URL, and reference code. That check found a bare reference code still present in the safe copy. The fix was not to hand-edit the output: a standalone uppercase-code rule was added to const RULES, and a regression test named finds standalone uppercase reference codes was added to src/lib/patterns.test.ts. The full journey test in src/App.test.tsx and the leak-check tests in src/lib/leakCheck.test.ts protect the broader promise.

  1. Name the user-visible condition, not just the implementation (“the safe copy contains none of the known sensitive values”).
  2. Make the condition observable in a test, smoke script, or browser check before you trust the feature.
  3. When a manual check finds a miss, encode that exact miss as a regression test, then fix the shared rule — not the one document that exposed it.
  4. State the edge of the check: this is a known-residual check, not a guarantee of anonymity. The same honesty belongs in any future privacy feature.

What this map does not claim

It is a code and behavior map, not a security audit or a guarantee of anonymity. Detection is best-effort; the model is English-centric; exact-string replacement does not resolve nicknames or pronouns; the leak check only knows implemented patterns and the approved cast. The app never persists the document, and the user remains responsible for reviewing the safe copy before sharing it.
